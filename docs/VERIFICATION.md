# Local verification

Verified on the implementation machine using the installed Node.js runtime and an isolated Playwright Chromium browser. These checks do not constitute farmer usability evaluation or evidence of increased income.

## Results

- TypeScript: `npm.cmd run typecheck` passes.
- Unit tests: `npm.cmd test` passes **34 tests across 7 files**.
- Production build: `npm.cmd run build` passes and generates the PWA manifest and precaching service worker.
- Browser tests: `npm.cmd run test:e2e` passes **13 tests**, using the production preview at `http://127.0.0.1:4173`.
- Production dependency audit: `npm.cmd audit --omit=dev` reports **0 vulnerabilities** at verification time.
- Whitespace: `git diff --check` passes.

## Exercised behavior

1. Sample dashboard, all five pages, rice-grain theme control, keyboard switching, and preference persistence.
2. Separate real seasons, sack-to-kilogram conversion, unknown costs, explicit zero, and reopen persistence.
3. Expense creation and editing without mixing planned and recorded values.
4. Saved scenarios retain their original baseline after the plan changes; expense records stay unchanged.
5. Partial receipts and cent-rounded final payments, with overpayment rejected.
6. Backup download, invalid-file rejection, preview, restore-as-copies, and subsequent reload.
7. Filipino interface, 390-pixel mobile navigation, no document-width overflow across pages, and reduced-motion behavior.
8. Production service-worker control, network-disabled reload, offline expense save, and another offline reload.
9. A new-device restore of a season whose optional dates are unknown.
10. Simulated local storage failure keeps the typed form values and shows an error.
11. Prior-budget copying and season archive/unarchive preserve historical expenses.
12. Rapid repeated submission writes one receipt; forms disable while saving. Database tests also serialize competing receipt writes and reject sale reductions below payments already received.
13. Changing harvest condition preserves the independently entered price condition and withholds mismatched break-even results after reopening.

The independent numeric fixtures include the ₱70,000 / 4,000 kg / ₱20 example, the F=₱60,000 and v=₱2/kg lower-harvest example, missing/zero inputs, incompatible grain conditions, break-even rounding, and invalid backup references and overflow.

## Visual inspection

Inspected desktop and phone layouts in light and dark modes. Dashboard screenshot evidence is generated by the browser tests in `test-results/`. Reviewed the dashboard, budget and scenario screens in the in-app browser. The theme icon was revised after user feedback to a diagonal rice grain with one textured lifting husk and a separate cream kernel.
